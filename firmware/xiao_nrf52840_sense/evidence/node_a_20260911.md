## Diagnostic path

The pristine Zephyr sensor sample and sensor shell both enumerated over USB but
reported `lsm6ds3tr-c@6a` as disabled. The I2C shell found address `0x6a` and
later read WHO_AM_I as `0x6a`, proving that the physical bus and sensor were
present. Changing the bus between 100 kHz and 400 kHz did not change the read,
so bus rate was rejected as the cause.

The board devicetree declares a boot-on fixed regulator and a 3 ms startup
delay. Inspection of Zephyr 4.4.0 showed that fixed-regulator initialization
configures the GPIO active, then enters `regulator_common_init()` with
`is_enabled=true`; that branch increments the reference count without applying
`startup_delay_us`. Merely changing the devicetree delay to 50 ms therefore did
not affect startup and the IMU remained disabled.

The passing bring-up firmware defers only the IMU device, waits 50 ms in
`main()`, then invokes its normal Zephyr driver initialization. This changed the
observed hardware result from disabled to ready and produced continuous
accelerometer and gyroscope samples. The workaround is local to the bring-up
application pending a production power-sequencing design.
