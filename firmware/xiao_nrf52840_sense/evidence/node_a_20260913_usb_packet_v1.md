## Software implementation

The packetizer preserves the existing direct LSM6DS3TR-C raw-count boundary,
ISR timestamp, clock epoch, independent sample/packet counters, bounded
drop-newest queue, and FIFO-status observer. It emits up to four samples per
packet as:

- 16-byte little-endian v1 header;
- four 26-byte sample records in this run;
- CRC-32C/Castagnoli over header and records.

After the diagnostic preamble, `main.c` never appends text to the binary stream.
Pending sensor-FIFO and firmware-queue overrun events are transferred once into
packet flags; sequence discontinuity is also represented. Transport
backpressure is not generated by this staging implementation and must remain a
separate validation item.

The host path is `scripts/capture_m1_usb.py`. It uses `pyserial==3.5` only for
byte acquisition, preserves the complete CDC stream as `.usb.bin`, writes
validated payloads to the frozen `.kimu` outer framing, and records parser/QC
events in `.events.ndjson`.

## Additional negative boundary check

board, so it began in the middle of an already-running USB stream. It is not
acceptance evidence. The parser recorded a CRC candidate and a truncated tail;

sample sequence values rather than hiding the mid-stream loss. Its artifacts
are retained with the `_run2` suffix for reproducibility of this boundary
